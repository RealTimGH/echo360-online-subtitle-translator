# 整句合并翻译：调研、选择和实现

调研及样本复核日期：2026-09-21。当前算法缓存版本：`sentence-merge-v2`。

## 设置位置

两个开关都保留在课程页的“翻译字幕设置”，但按用途分开放置：

- **整句合并翻译**：与“目标语言”一起放在“翻译行为”组中。它改变翻译输入；切换后需要重新加载或翻译。
- **英文也显示合并整句**：紧跟“双语字幕”，缩进并说明前置条件。它只改变插件的英文显示，不发起翻译请求。

这个浮层本来就提供翻译服务入口和目标语言，并非纯粹的外观设置。用户需要结合当前课程试听、比较合并效果，所以保留现场入口；插件完整设置继续负责服务、密钥、模型和请求参数。两个开关不在两处重复提供，以免用户误以为存在全局值与课程覆盖值。设置仍沿用原来的偏好持久化方式，并不按课程隔离。

两个开关默认均为 false。英文选项要求主开关开启、插件负责双语显示，原生 CC 注入或仅显示译文时禁用；禁用时保留用户的选择。主开关在翻译进行中变化时，当前任务结束后按最新设置重跑，避免并发任务覆盖。英文开关仅刷新显示。

## 行业方法与技术选择

- [Netflix Subtitle Templates](https://partnerhelp.netflixstudios.com/hc/en-us/articles/219375728-Timed-Text-Style-Guide-Subtitle-Templates)区分字幕事件、语言分段和阅读约束，要求换行尽量尊重语法，避免分开冠词与名词、主语与动词等。其规范允许人工编辑，但本项目遵守用户的原文不改写要求，不采用删词、改述和去重策略。
- [NLTK Punkt](https://www.nltk.org/api/nltk.tokenize.punkt.html)通过缩写、搭配和句首词消歧，说明遇到句号不能直接断句，缩写也可能同时出现在真正的句尾。
- [spaCy Sentence Segmentation](https://spacy.io/usage/linguistic-features#sbd)提供依存分析、统计断句、标点规则、自定义规则等路径。规则适合轻量确定性处理；统计方案需要模型与适用领域验证。
- [Where's the Point?](https://arxiv.org/abs/2305.18893)研究不依赖标点的统计断句，适合说明无标点文本为什么不能只靠句号恢复句界；它不意味着在本项目课程上有已验证的准确率。

- [Netflix Timed Text Style Guide: Subtitle Timing Guidelines](https://partnerhelp.netflixstudios.com/hc/en-us/articles/360051554394-Timed-Text-Style-Guide-Subtitle-Timing-Guidelines)要求字幕与音频同步，并规定最短显示时长、相邻事件之间的间隙，以及用“借时间”合并过短事件，而不是让一行闪过。
- [AppTek IWSLT 2023](https://aclanthology.org/2023.iwslt-1.22.pdf)在没有词级时间戳时，按字符比例线性插值额外字幕块的时间边界。
- [Direct Speech Translation for Automatic Subtitling](https://arxiv.org/html/2209.13192)比较了把源时间强加给译文、按字符/编辑距离投影、以及语义词对齐；无词级时间戳时，字符比例投影是可运行的回退，不是精确对齐。
- [Subtitle Edit 讨论：按句末标点切分并按内容比例分配时间](https://github.com/SubtitleEdit/subtitleedit/discussions/10115)代表常见字幕工具的做法：先在句界切开，再按字符或词数比例重分配原时间窗。

跨句显示不采用强制对齐或额外模型。译文保持整句；只把跨两句的那条原字幕的显示时间按该条内部源文字符比例切开。叠加显示仅作为过短时间窗的回退。这与 Netflix 对最短时长的要求一致，也避免了按中文字数切割译文。

选用浏览器本地的“句界消歧 + 长句分句候选 + 时间/长度保护”，不引入 Python 服务、模型下载或额外断句 API。合并前从全份 VTT 建立原文映射，翻译内容仍交给用户选择的服务。单纯把最大合并条数改为两三条会重新产生大量半句；直接让 LLM 改写成完整句则不符合原文保真要求。

## 样本发现

使用用户提供的三份 VTT，共 4,868 条原字幕，全部在本地分析，未发送给翻译服务。详细数字与例子见[真实字幕分析报告](sentence-merge-sample-analysis.md)。

主要问题是讲课口语用逗号串联多个分句，而旧版只在 cue 末尾寻找句末标点。并非大量 cue 都横跨两句：这些样本只有两处明确的 cue 内句界，均在 Week 02 Supply Chain 的百分比讲解中。`p.m.`、`a.m.`、`i.e.` 不能算成额外句子。

源文件还包含几十秒的低质量 ASR 单条字幕、词语重复和不自然的识别结果。这些内容保留，不借合并修正。

## v2 分段顺序

1. **先建立安全连续区间。** 说话人改变、独立音效/音乐、空字幕、无效/零时长/倒序/重叠时间、超过 1500 ms 的停顿阻止跨 cue 合并。NOTE CONF 元数据不进入字幕。
2. **再识别真实句界。** 在连续文本中查找句末标点，包括 cue 内部。排除人名缩写、首字母、日期/学术缩写、小数、网址内部句点；结合后文识别 `U.S. We…` 等缩写兼句尾情况。省略号后的小写延续、问句引号后的叙述短语采用保守规则。
3. **短而完整的句子立即结束。** 不为了凑批次而追加下一句，也不因为 cue 开头大写就贸然断句。
4. **长句优先找独立分句。** 超过 28 个英文词时才考虑逗号、分号、冒号后的分句；需要主语及有限的谓语特征，排除 `you know,` 等口头填充。保护 `If …, we …` 等前置条件以及 `not only … but …` 等关联结构。这是保守启发式，不是完整英语句法分析。
5. **过长时有序兜底。** 合并上限为 6 条源 cue、18 秒、48 个英文词、360 个可见字符；字符上限同时受服务 `maxChars` 约束。优先在已有标点后切分，再回看可用 cue 边界，尽量不把 `the`、`because I`、助动词、数字等留在断点前。兜底可能产生从句或半句，不声称它们都是独立完整句。无法安全细分的单条超长源 cue 保留。
6. **保持字词和来源映射。** 每个翻译单元记录原 cue 索引。原文的所有字词、重复词、标点与顺序不变，不补词或补标点；分段处仅规范分隔空白。英文显示保留 VTT 样式信息，必要时为片段配平样式标签。翻译请求移除 voice/style/timestamp 元数据并压平换行，避免把反复出现的 `<v Speaker 1>` 送给翻译服务。
7. **跨句 cue 只切开显示时间。** 一条源字幕属于相邻两句时，按该条内部各句片段的源文字符比例分配原时间窗，并保证每片至少约 400 ms。译文仍是完整句子。过短则退回叠显示。覆盖层的中英文事件保持一对一；Transcript 仍按原字幕行堆叠。

28/48 词等数值是结合这三份讲课字幕采用的工程阈值，不是 Netflix 或其他行业标准。

## 翻译、显示及异常映射

例如原字幕是：

```text
This is
 a sentence. The next
 one continues.
```

翻译服务收到两个单元：`This is a sentence.` 和 `The next one continues.`。两份中文都保持完整，不按字数切割。

显示层把中间那条跨句字幕的时间窗按该条内部的英文字符比例切开：前半段只显示第一句完整译文，后半段只显示第二句完整译文。同一句若覆盖多条原字幕（包括中间很短的 ASR 空隙），覆盖层会把内容相同的相邻事件连成一条，避免字幕消失再以同样文字出现。关闭英文合并时，切开后的英文仍是原字幕用词，只是同一条原文会占用两个衔接的时间片；开启时英文也按对应整句切换。播放器原生英文轨不变，静音间隙不被填平。Transcript 面板继续使用原始英文行，跨句行仍保留两句译文，便于对照。

切分点来自该条字幕内部各句片段的源文字符数，并保证每个时间片至少约 400 ms；更短的跨句字幕仍叠显示两句，以免闪一下。这不是词级时间戳，也不按中文字数猜时间。

服务侧分组 VTT 的范围覆盖参与的原 cue，故相邻翻译单元可能重叠，甚至有相同时间范围。它们是翻译输入容器，**不会直接作为最终播放字幕挂载**。结果按精确时间范围匹配，重复范围还要求分组编号匹配；缺失/乱序结果不能推动后面的句子前移。预览和失败状态先在分组层处理，再映射到原 cue。一条源字幕对应多组时，Transcript 保留各组完整结果；某句失败不会覆盖同一行另一句已成功的译文。

缓存按 `cacheKey` 分槽保存，合并（`sentence-merge-v2`）与未合并结果可以同时保留；同一字幕 URL 不再按合并后文本哈希。没有固定条数上限；只有浏览器本地配额不够时才会丢掉较旧的槽。强制重新翻译只清当前槽。分组规则不兼容时再升版本号。英文显示开关不影响缓存。命中后仍校验分组条数是否与当前合并结果一致。请求批次可以容纳多个独立单元，但不会把它们拼成一个待翻译字符串。手动 AI 导入/导出协议保持原样。

## 验证与局限

自动化覆盖：句内边界、跨 cue 半句、带样式文本保真、条件句/列表/口头填充、缩写/数字、上下文句尾、长句限幅、原始时间保留、同时间范围的多组结果、缺失及乱序预览、失败映射、真实 provider 适配器的重叠时间与编号保持、控制器接入和开关交互。

可在本地复核新的课程字幕：

```bash
node scripts/analyze-sentence-merge.mjs '/path/to/transcript.vtt'
```

脚本输出长度分布、共享 cue 数、原文保真、映射完整性、英文开关关闭时的不变性。可用 `--baseline /path/to/previous/sentence_merge.js` 对比旧算法。脚本不会联网，也不会输出完整课程文本。

统计只证明分段长度和映射保真，不等于翻译准确率测试。未使用真人标注句界、音频强制对齐或付费服务做盲评；错误标点、无标点语音、没有标记的说话人变化、极长条件句仍有歧义。跨句显示使用源文字符比例估计切换点，不是词级对齐；过短时间窗仍可能叠显示两句。
