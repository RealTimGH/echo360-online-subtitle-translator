# 部分翻译的保存、补译与诊断

调研日期：2026-09-22。

## 问题与选择

原流程仅在失败数为零时写入缓存。141 条成功、1 条失败时，当前页可显示成功译文，但离开后没有可复用的进度；再次一键翻译会重复请求整份字幕。

采用部分进度检查点：成功结果与失败位置一并保存，保留源字幕与配置身份。再次一键翻译时，验证源字幕完全一致、时间轴与失败位置有效，只提交失败字幕，并将新译文合回原位置。部分进度不能作为完整缓存命中。明确的“重新翻译”继续清除当前结果并整段重做；错误卡片使用“重试失败字幕”。

这是逐项确认、局部重试的应用。AWS 的 [SQS 部分批次响应说明](https://docs.aws.amazon.com/prescriptive-guidance/latest/lambda-event-filtering-partial-batch-responses-for-sqs/benefits-partial-batch-responses.html)说明只重试失败消息可以避免重复处理成功项。这里借鉴处理原则，不引入消息队列。暂时性故障继续使用已有的有限重试和退避；[AWS Retry with backoff](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/retry-backoff.html)强调幂等与按错误类型决定重试。

## 原文不变不一定失败

目标语言字符检测只能作为启发式，数字、符号、网址、课程代码、单字母标签等合理结果可能没有汉字。孤立的 `p.` 缺乏上下文，可能是标签、缩写或识别残片；不能仅凭这一文本断言应译成哪个中文词。对明确的窄范围中性文本，允许服务返回原文；仍拒绝普通英文单词或句子被直接回显，不对所有短文本放行。

[Google Cloud Translation 排错文档](https://docs.cloud.google.com/translate/troubleshooting)指出过短的输入可能无法可靠识别源语言。这能说明短输入的局限，但不构成 Google 网页端点的接口保证，也不能证明某次 `p.` 响应的实际内容。

## 排查信息

失败信息需要同时给出字幕 cue 序号、VTT 行号、时间段、原文摘要及错误码，避免将请求批次号误认为原字幕序号。展示采用文本节点，摘要有长度上限；完整失败位置用于补译，诊断示例的截断不能导致遗漏待重试字幕。

## 边界

- 更换目标语言、服务或整句合并策略时沿用独立的配置缓存身份。
- 同一源 URL 的内容发生变化时，部分进度必须验证原始 VTT，不能仅依靠 URL。
- 补译再次失败时保留此前成功的结果，不能让小批次全失败导致整份结果丢失。
- 补译以 cue 为单位：一个 cue 有多行时，其中一行失败会重试该 cue；其他已完成的 cue 不会重发。合并响应和实时预览时只更新原先失败的文字行，即使本轮把同一 cue 中原先成功的行翻译失败，也不会覆盖已有译文。进度按实际重试行数计算，避免提前显示完成。整句合并模式下，cue 是发送给翻译服务的合并字幕，诊断同时给出原始 cue 映射。
- 本地存储写入失败必须显示警告；当前页保留结果不等于跨页面保存成功。
- 旧版本没有持久化的部分结果无法在升级后追溯恢复。

- 完整失败位置同时保存 `failed_cues` 和 `failed_lines`，与最多 50 条的诊断示例分开。旧版或自定义服务的结果如果不足以精确确定多行 cue 中的失败行，就不能安全续传，需要重新翻译。
- 当前页内存断点不会覆盖更新的完整缓存或手工导入；写入失败时仍保留内存断点供当前页补译。
- 混合服务按文字行保留已验证结果：其他候选服务失败不会擦除先前成功的行。有成功结果时返回可保存的部分结果；全失败时仍提供完整失败位置，取消或任务失效不会转为可保存成功。
